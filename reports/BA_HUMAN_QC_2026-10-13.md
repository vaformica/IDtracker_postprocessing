# A quick human QC step for BA traces

AI-written implementation record by Codex, 13 October 2026.

Vince requested a quick visual skim before trusting BA outputs or deciding which beetles to exclude. I read the current “Add BA single-animal videos” chat and based this page on its existing additional-100 collection. That chat is actively testing gap recovery; this new screening page uses the previously delivered raw/proposed arrays and leaves its active experiments, original reviews, browser storage keys, and scores unchanged.

Open http://127.0.0.1:8798/START_HERE.html while the local server runs. The separate package is `outputs/ba_human_qc_20261013/`. If the server stops, run its `START_QC.command` and reopen that address. It reads existing full videos from `/Users/New/Downloads/BA_additional100_recovery_20261012/` through local links; moving that media folder requires rebuilding those links. This is a local viewer, not a Firebird or public deployment.

The workflow is: skim the gallery in existing QC-priority order, compare raw baseline and proposed recovery paths, and click a path point or time plot when something looks odd. The same full video supports a ten-second excerpt around the selected time or full-run playback. Frame stepping, an external seek slider, and 0.5×/1×/2×/4× speed are provided. Video needs no track position to remain visible. Missing coordinates break plotted lines; human-excluded frames are counted separately. Raw baseline sometimes means the attributed light-exclusion tracking rerun, not the withdrawn predecessor; the inherited QC reasons disclose that context.

Choose Looks usable, Needs closer review, or Recommend exclusion. One or more issue buttons record jumps, missing gaps, possible turtling, camera/light changes, wrong object/shadow, injury/abnormal behavior, or other problems. Optional original-frame intervals locate problems without creating posture labels or exclusions. The reviewer states whether the decision followed a trace skim, a short video, or the full video. Merely playing a video does not silently assert that it was reviewed. Earlier attributed notes and their original scope are displayed separately, not converted into fresh decisions.

The JSON export (`ba-human-qc-v1`) contains the dataset fingerprint, run ID, category list, reviewer, timestamp, scope, notes, optional intervals, drafts and revision history. JSON is the authoritative portable record; CSV is a compact summary. Browser saving is convenient but users should download JSON. Imports reject incompatible datasets, invalid categories and out-of-range intervals. Conflicting imported decisions preserve the local decision and incoming record in history. An exclusion recommendation does not delete a beetle or change analysis denominators; downstream inclusion choices must remain explicit and attributed. “Looks usable” records a skim, not biological approval or validation of all proposed coordinates.

Build code: `build_ba_human_qc.py`, `ba_human_qc_template.html`, `ba_human_qc.js`. Tests: `tests/test_ba_human_qc.cjs` and `tests/test_ba_human_qc_ui.cjs`. Ten schema/export checks and six UI-logic checks passed. All 100 trace lengths, media references, and missing/excluded counts were checked. Browser inspection confirmed gallery rendering, seeking to frame 3000, 4× playback and the short-excerpt path. No human decisions were entered during browser testing. These checks do not establish scientific correctness of the traces.

Use this as the human screening step before a later inclusion/exclusion or repair batch. It is intentionally faster than scoring hundreds of individual recovery scenes. Turtling detection and automatic QC remain supporting hints; human findings can become an attributed repair queue or a new scored benchmark. No detector changes, automatic exclusions, new tracking jobs or dyadic work were made here.
