02 / What the program infers

A second path, with its assumptions visible

IDtracker.ai supplies observations. The PSC model may place a hidden beetle with a visible partner or compatible blob while a pile is supported. If it cannot support a location, that beetle stays missing. Raw and inferred measurements are never silently combined.

04 / Ready for the next task

How to start safely

  1. Confirm inputs. Review TOML animal count, tracking start, arena and fungus ROI order, and choose an inclusive frame window.
  2. Launch the shared interface. Use python group_firebird_gui.py for all supported groups, python dyadic_firebird_gui.py for its dyad filter, or python idtracker_toml_gui.py to submit tracking. The CLI is python run_group_pipeline.py --help.
  3. Write a new versioned result. Preserve source TOMLs and IDtracker trajectories. Check the manifest for PSC 1.5.1, processor 0.8.1-group, source hashes and UNREVIEWED status.
  4. Verify, then watch. Count frame/animal rows and encoded video frames; inspect both PDFs, raw/PSC tables and ZIP integrity. Review flagged identity/contact episodes before using the numbers as biological conclusions.

The local 2026-09-28 software run passed 133 tests. The two official releases record identical PSC core code and parameter values. This proves code parity, not biological identity accuracy.

05 / The honest stopping point

Ready for review, not ground truth

The next useful work is to review difficult piles, identity conflicts and raw-versus-PSC disagreements, record attributed corrections, and decide whether the model needs another version. Any changed rules or time windows deserve fresh versioned outputs. Do not mix earlier releases into these without checking their manifests.

The historical processor.py / root VERSION=0.8.1 is not the current PSC processor. The current implementation is six_beetle_processor.py with persistent_groups.py. See future-task notes and the archived prototype guide.
